'@amritk/mini-native': minor

Add focus, the composition seams on a new `@amritk/mini-native/composition` subpath, and the rest of the input surface.

**Focus** is the first pair of METHODS the `Host` contract has grown, and it earned it the hard way: no existing method can express it and every real app needs it — advancing to the next field, trapping and restoring focus in a modal, moving a screen reader to an error. Both are optional, so a target with no notion of focus does not have to fake one. `focus(element)` is a call rather than a prop because a `focused={true}` prop has no correct meaning the moment the user taps elsewhere: the prop still says `true`, the element is not focused, and nothing can honestly reconcile the two. `autoFocus` covers the first moment, and defers to the end of the tick — an element that is not in the tree yet cannot take focus on any target, so applying it eagerly would leave the prop looking applied and silently never working.

**`createContext`** exists here for a reason `@amritk/mini` deliberately rejects: the things that vary by platform — theme, insets, navigation, locale, colour scheme — are exactly the things you do not want in a component's signature. Prop-drill them and every intermediate component grows a platform-shaped prop it does not use, which is write-once eroding one signature at a time.

The hard part was not the API. `Show`, `For`, `Dynamic`, and `ErrorBoundary`'s retry all build their subtrees LATER, inside an effect, long after a provider returned — so a theme provided at the app root would reach every component except the ones behind a conditional or in a list, and would fail silently by falling back to a plausible default. `renderChild` and `list` now capture the ambient frame when they are called, which is during the component body and therefore inside whatever provider wraps it, and restore it around every build afterwards. Core carries that frame without knowing its shape, which keeps the feature out of the entry every app pays for: the `.` bundle grew 37 gzipped bytes and stays under budget.

`provide` takes a **function**, not an element, and that is forced by the runtime rather than chosen: JSX builds nodes immediately, so in `<Provider>{<Child/>}</Provider>` the child is constructed as an argument, before the provider ever runs.

**`Portal`** takes an explicit target rather than asking the host for an overlay root — that would mean a new method on the contract and a per-target answer to "where is the top of the screen", a question the host would guess at and the app already knows. What stays behind is a presentational placeholder, which is what ties the moved subtree's lifetime to the place that wrote it: unmount that and the sheet goes with it, rather than being orphaned in the overlay root with its bindings live.

**`ErrorBoundary`** catches a throw while building. Components run exactly once, so a throw part-way through leaves a half-built tree with no second render to recover on — a blank area on the web, a dead app on a device. It covers the initial build and every retry, each in its own scope so a retry cannot leak the failed attempt's bindings. It does not cover a throw inside an effect, a handler, or a promise: those happen after every component has finished running and belong to whoever started them.

**Input completeness.** `submitLabel` and `onSubmit` are the portable replacement for the web's Enter-to-submit-inside-a-`<form>`, with no form element in the vocabulary — `enterkeyhint` is a real HTML attribute, so the browser raises the same confirm key a device does. `onSubmit` does not fire on a multiline field, where the key inserts a newline on every target, and does not fire on the Enter that chooses an input-method candidate: typing Japanese or Chinese ends nearly every word with one, and submitting on it is the classic bug in this feature — invisible to anyone testing in English. `autoComplete` covers the subset that maps onto web `autocomplete` tokens, iOS `textContentType`, and Android autofill hints at once, spelled `phone` rather than `tel` so it matches `keyboard` — translating it is the host's job, exactly as it already is for `keyboard="phone"` becoming `type="tel"`.

`createLynxHost`'s second parameter is now an options object (`{ environment, focus, blur }`) rather than a bare environment, for the same reason as before: the PAPI subset this adapter drives is element-level, and everything outside the element tree varies by engine version with no fake to test against.
