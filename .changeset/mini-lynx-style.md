Add the layout reset and the token layer — the style half, with its reasoning in `docs/mini-lynx-style.md`.

**The reset is the floor, not a nicety.** Everything cross-platform up to now was additive: new props, new optional host fields, nothing that existed behaving differently. Style is not, because the two targets disagree about what an element *is* before a single declaration is written — `display` is always flex on a device and `block` here, `flexDirection` is `column` there and `row` here, `flexShrink` is `0` there and `1` here. An unstyled container with two children stacks vertically on a device and horizontally on the web, and no amount of careful component authoring above that papers over it. `createDomHost()` now installs one stylesheet that closes it.

Three decisions in it are worth knowing. Every rule is wrapped in `:where()`, so its specificity is zero and a single class or a `style` prop beats it without `!important` — a reset that wins arguments with the code above it is one people work around, and the workarounds are worse than the divergence. It is scoped by a `data-mn` attribute rather than by tag name, so an app embedding this runtime beside other markup keeps its own page; `createDomHost({ reset: false })` declines it entirely for a guest in a page it does not own. And **text inheritance stops at a container**, matching Yoga rather than CSS: a colour set on a container reaches its text on the web and silently does not on a device, and picking the strict target's semantics is the same call `ContainerChildren` already makes. The base it re-asserts is `--mn-font` / `--mn-color` rather than `initial`, because `font: initial` is a serif face — an app that had never heard of this file would otherwise come up in Times.

It deliberately does not clip overflow, which looks like a missing row in that table. The two native platforms do not agree with each other about clipping, and clipping every container on the web silently breaks shadows, focus rings, and every popover outside a `Portal` — a large behavioural claim to make on an app's behalf to close a difference that is visual rather than structural.

**Tokens resolve to style objects, not classes**, settling the fork the cross-platform note left open. Classes are genuinely cheaper on the web and meaningless on a headless host and different again on a native engine; a style object is the only shape every target already consumes. Class extraction stays available later as a web-only optimisation behind the optional plugin, where skipping it costs bytes rather than correctness — the ordering is the point, because choosing classes first would have left the other two hosts carrying a translation layer that could never be removed.

**The theme is a signal**, and that is load-bearing rather than stylistic: a component runs exactly once and therefore reads context exactly once, so a plain `Theme` would be whatever it was at boot, forever. `ThemeContext` holds a `ReadonlySignal<Theme>`, so a dark-mode switch reaches the whole tree with no re-render and no invalidation pass — the same element, with a style mutated. Not providing a theme is a supported state; the fallback is a real one, so a component renders correctly on its own in a test.

`Text` and `Heading` gain `size` and `tone`; `Stack` and `Row` gain `gap`, taking a named step of the theme's spacing scale rather than a number. **`size` and `level` stay two props, always** — a real page needs an `h2` that renders small and large text that is not a heading at all, and coupling them is how authors start choosing heading levels by how big they want the text. `Text` has no `role` or `level` on its surface at all, so the split is enforced rather than documented.
